# Moby Family — семейный банкинг

Хакатонный прототип пакета «Фэмили»: родитель оформляет пакет и управляет правами,
ребёнок пользуется картой в рамках выданных лимитов. Демонстрируется **с реальных
телефонов iPhone и Android**.

## Стек

- **Приложение:** Expo SDK 58, React Native 0.88, Expo Router, TypeScript.
  Запуск — Expo Go на двух телефонах, без сборки и без Apple Developer.
- **Сервер:** Node 22, Fastify, zod, jsonwebtoken, WebSocket.
- **База:** Supabase (PostgreSQL). RLS включён, политик нет: клиент в базу не ходит,
  только сервер через service_role.

## Демо-доступы (данные уже в базе)

**Демо-данных в базе нет — всё создаётся с нуля, как в проде.**
Регистрация: телефон → код `1111` (пока включён демо-режим SMS) → «Я родитель / Я ребёнок» →
имя и фамилия → пакет «Фэмили». Дальше родитель добавляет ребёнка и получает его код доступа,
ребёнок входит своим номером и этим кодом.

### Telegram-бот (бесплатно): коды входа и уведомления
1. В Telegram: `@BotFather` → `/newbot` → скопировать токен.
2. Написать своему боту любое сообщение, затем открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять `"chat":{"id":...}`.
3. В `server/.env`: `TELEGRAM_BOT_TOKEN=...`, `TELEGRAM_CHAT_ID=...`, затем `systemctl restart moby-api`.
4. Проверка: `curl https://malanka.jaraslau.dev/moby/health` → `"telegram": true`.

Дальше код входа и все уведомления родителю (запрос ребёнка, платёж ЕРИП, перевод по номеру)
приходят в этот чат. Реальные SMS вместо бота: `SMS_PROVIDER=twilio` (платно)
или `SMS_PROVIDER=twilio` (платно) + соответствующие ключи в `server/.env`.
Для прода также убрать `DEMO_OTP`.
Адрес API: `https://malanka.jaraslau.dev/moby` (nginx на VPS → Node API, TLS от Cloudflare).

## Что демонстрируется на защите

1. **Два телефона вживую.** Родитель входит по номеру, создаёт пакет «Фэмили»,
   добавляет ребёнка, подписывает согласия, выпускает карту и выдаёт доступ.
   Ребёнок входит своим номером и кодом доступа.
2. **Правила работают на сервере.** Попытка оплаты в категории 18+ или азартных играх
   отклоняется на API, а не в интерфейсе; лимиты и выключенные операции тоже.
3. **Живой обмен.** Запрос ребёнка всплывает у родителя сразу, подтверждение меняет
   экран ребёнка без перезагрузки.
4. **Журнал.** Каждое согласие и изменение прав попадает в `audit_log`.
5. **Счета и переводы.** Ребёнок на вкладке «Счета» перекладывает деньги между карманными,
   копилкой и целью. Вклад по возрасту недоступен: ребёнок оставляет запрос, а счёт открывает
   родитель, подтверждая запрос — юридически договор заключает родитель, подтверждение = разрешение.
6. **Экран открытия.** Заставка с логотипом при запуске (пока анимация-заглушка; готовый
   ролик встанет на её место без правок логики).
7. **ЕРИП и перевод по номеру.** Ребёнок не платит сам: он оставляет заявку (код ЕРИП или номер
   телефона + сумма), родителю приходит уведомление, он **проводит пальцем вправо** — и только
   тогда деньги списываются. Тот же свайп подтверждает любые важные операции.
8. **Банковская база в UI.** Крупный счёт, одно главное действие «Закинуть деньги» в два касания,
   переводы между счетами. Дизайн меняется в `mobile/src/theme/tokens.ts` и `mobile/src/ui/banking.tsx`.

Демо-режим: если адрес API не задан, приложение работает на локальных данных —
стенд не падает без сети. Код подтверждения на защите — `1111`.
