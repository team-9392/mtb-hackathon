# Каталог наград Moby Family

Весь контент магазина наград живёт в коде — в файле `server/src/rewards.ts`.
Чтобы добавить, изменить или убрать награду, достаточно отредактировать массив
`REWARDS` и перезапустить сервер. Отдельная миграция или запись в БД не нужна.

> ⚠️ **Никогда не меняйте `id` уже выданных наград.** В таблице `purchases`
> хранятся ссылки на этот id и выданный промокод. Если переименовать id,
> купленная награда «потеряется» у пользователя, а история покупок сломается.
> Менять можно цену, тексты, партнёра, сортировку — но не id.

---

## 1. Структура записи

Одна награда — это объект такого вида:

```ts
{
  id: "r-cafe-latte",              // уникальный id, латиница через дефис, с префиксом "r-"
  audience: "child",               // для кого награда: "child" или "parent"
  kind: "promo",                   // тип: "promo" | "theme" | "perk"
  price: 300,                      // цена в монетах Moby
  title: { ru: "...", be: "..." }, // название на русском и белорусском
  desc:  { ru: "...", be: "..." }, // описание на русском и белорусском
  value: "MOBY-CAFE",              // смысл зависит от kind (см. ниже)
  code:  null,                     // фиксированный промокод или null
  partner: { name: "...", logo: "cafe.png" }, // партнёр или null
  sort: 9,                         // порядок вывода, по возрастанию
}
```

### Поля подробно

| Поле | Что значит |
| --- | --- |
| `id` | Уникальный строковый идентификатор. Формат: `r-` + латиница через дефис (`r-theme-ocean`). Используется в URL покупки (`POST /rewards/:id/buy`) и в `purchases`. |
| `audience` | Кому показывать награду: `"child"` — ребёнку, `"parent"` — родителю. Сервер отдаёт в `GET /bonuses` только награды своей роли. |
| `kind` | `"promo"` — промокод партнёра; `"theme"` — тема оформления; `"perk"` — внутриигровая выгода (без внешнего промокода). |
| `price` | Цена в монетах Moby. Списывается при покупке и пишется в `coin_ledger`. |
| `title` / `desc` | Локализованные название и описание. Обязательны обе локали: `ru` и `be`. |
| `value` | Зависит от `kind`, см. раздел «Типы наград». |
| `code` | Для `promo`: `"MOBY5"` — фиксированный промокод, `null` — сервер сгенерирует код сам. Для `theme`/`perk` обычно `null`. |
| `partner` | `{ name, logo }` или `null`, если награда не привязана к партнёру. `logo` — только имя файла, не путь. |
| `sort` | Число, по возрастанию. Определяет порядок карточек в каталоге. Держите уникальным. |

---

## 2. Как выбрать `audience`

- `"child"` — награды, которые покупает ребёнок на заработанные монеты:
  партнёрские промокоды, детские темы, перки (лишний час экрана, стикеры).
- `"parent"` — награды для родителя: кофе, такси, книги, расширенные лимиты,
  тема для родительского кабинета.

Один и тот же `value` (например, тема `ocean`) может встречаться в обеих
аудиториях — это разные записи каталога, и у каждой свой `id`.

## 3. Как задать цену

- Цена — целое число монет. Ориентиры: детские награды **150–600**,
  родительские **300–900**.
- Тесты/квесты дают **40–180** монет за прохождение, поэтому в каталоге должны
  быть недорогие позиции (150–300), чтобы прогресс был заметен быстро.
- Исторические записи `r-cash5` (500) и `r-cash10` (900) не трогаем —
  их цена зафиксирована уже выданными покупками.
- Цена должна быть `> 0`. Пересчёт баланса выполняет сервер.

## 4. Типы наград (`kind` и `value`)

### `kind: "promo"` — промокод партнёра
`value` — короткий префикс/текст скидки, по которому партнёр понимает акцию
(например, `"MOBY-CAFE"`).
`code` управляет тем, кто придумывает сам код:

- `code: "MOBY5"` — **фиксированный промокод**. Пользователь всегда получает
  ровно этот код.
- `code: null` — **генерация на стороне сервера**. Сервер сам создаст
  уникальный код (вида `MOBY-XXXXXX`), когда пользователь купит награду.

Не делайте один фиксированный код у нескольких наград: он должен быть
уникальным, иначе акция не сработает.

### `kind: "theme"` — тема оформления
`value` — id темы, и он **обязан ссылаться на существующую тему**. Поддерживаемые
id: `default`, `graphite`, `ocean`, `sunset`. Не придумывайте новые id, пока
тема не добавлена в клиент, — интерфейс её не отрисует. При покупке сервер
записывает `value` в поле `theme` пользователя.

### `kind: "perk"` — перк
`value` — короткий токен того, что даёт награда (например,
`"extra-screen-hour"`, `"extended-limit"`). Человеческое пояснение пишите в
`title`/`desc`; сервер использует `value` как признак выгоды.

## 5. Фиксированный код или автогенерация

| Задача | Что писать |
| --- | --- |
| Промокод известен заранее (акция банка) | `code: "MOBY5"` |
| Код должен быть уникальным у каждого | `code: null` |
| Награда не промокод (тема, перк) | `code: null` |

При `code: null` для `promo` сервер генерирует код сам и сохраняет его в
`purchases`, после чего возвращает клиенту. Ничего дополнительно делать не нужно.

## 6. Логотип партнёра

1. Положите PNG-файл в каталог `server/assets/partners/`
   (каталог создайте, если его ещё нет).
2. В поле `partner.logo` укажите **только имя файла**, например `"cafe.png"`.
   Путь и корень `assets/partners` подставляются сервером.
3. Ожидаемые файлы: `cafe.png`, `cinema.png`, `trampoline.png`,
   `stationery.png`, `taxi.png`, `books.png`.
4. Форматы: **PNG** (основной), допустимы также WEBP/JPG, но для иконок лучше
   PNG с прозрачностью.
5. Рекомендуемый размер — **~256×256 px**, квадрат, логотип по центру с полями.
6. Названия партнёров в каталоге — правдоподобные форматы (кафетерий, кинотеатр,
   батутный парк, канцелярский магазин, служба такси, книжный). Не указывайте
   их как официальных партнёров бренда и не используйте чужие логотипы.
7. Если партнёра нет — ставьте `partner: null`.

## 7. Как проверить изменения

1. Запустите сервер в dev-режиме:
   ```bash
   cd /Users/jaraslaukunin/mtbhackathon/server
   npm run dev
   ```
   (или `npx tsx watch src/index.ts`).
2. Проверьте типы, не запуская сервер:
   ```bash
   cd /Users/jaraslaukunin/mtbhackathon/server
   npx tsc --noEmit
   ```
   Сборка должна проходить без ошибок именно в `rewards.ts`.
3. Откройте `GET /bonuses` под пользователем нужной роли (детский или
   родительский токен). В ответе в массиве `rewards` должны появиться ваши
   награды в порядке `sort`, с правильными `title_ru`/`title_be` и ценой.
   Родительские награды не должны попадать в детский ответ и наоборот.
4. Если меняли фиксированный код — проверьте покупку
   `POST /rewards/:id/buy`: в ответе `code` должен совпасть с заданным в
   `rewards.ts`. Для `code: null` должен прийти сгенерированный код.
5. Проверьте, что баланс списался корректно и позиция появилась в покупках.

## 8. Деплой

1. Внесите правки в `server/src/rewards.ts`.
2. Прогоните `npx tsc --noEmit` — ошибок быть не должно.
3. Соберите сервер: `cd server && npm run build`, затем перезапустите процесс
   (`npm start` или как настроен прод-запуск). Контент подхватывается при старте.
4. Логотипы из `server/assets/partners/` должны попасть в артефакт деплоя вместе
   с сервером — иначе карточки партнёров останутся без картинок.
5. После деплоя откройте `/bonuses` прод-стенда и убедитесь, что каталог
   отдаётся корректно.

## 9. Чек-лист перед коммитом

- [ ] `id` новые и уникальные, ни один существующий `id` не переименован.
- [ ] Обе локали `ru` и `be` заполнены, белорусский текст без русских слов.
- [ ] `price` в допустимом диапазоне и `> 0`.
- [ ] `sort` уникален и по возрастанию.
- [ ] Для `theme` `value` — один из `default`/`graphite`/`ocean`/`sunset`.
- [ ] Для `promo` явно решено: фиксированный `code` или `null`.
- [ ] Имя `partner.logo` совпадает с реальным файлом в
  `server/assets/partners/`.
- [ ] `npx tsc --noEmit` проходит чисто.
