# Moby Family – бэкенд, вход по номеру и визуальный язык

Предложение по развитию прототипа: реальная база данных, свой сервер, вход по номеру
телефона и «тихий» премиальный интерфейс банковского уровня.

---

## 1. Короткое предложение

1. **База данных** – PostgreSQL. Одна схема на всё: семьи, дети, карты, согласия, права,
   лимиты, операции, цели, квесты, запросы, уведомления, аудит.
2. **Сервер** – Node API (Fastify) на VPS с Ubuntu, база – **Supabase** (managed PostgreSQL).
   Node держит бизнес-логику, OTP, JWT и WebSocket для живого обмена между телефонами
   родителя и ребёнка. Приложение в базу не ходит вообще – только в API.
3. **Вход по номеру** – телефон → код из SMS → код приложения (4–6 цифр) → биометрия.
   На защите код подставляется демо-значением `1111`, адаптер под реального SMS-провайдера
   включается одной переменной окружения.
4. **Дизайн** – в основе спокойный минимализм «Искры» БНБ-Банка (тёмная тема, воздух, один
   акцент), в детском контуре – тёплая карточная подача Moby от МТБанка. Это два визуальных
   регистра одного продукта: «взрослый банк» и «детская часть», а не две разные поделки.

---

## 2. Архитектура

```
iPhone (Expo Go)            Android (Expo Go)
   │  HTTPS  REST                 │
   └──────────┬───────────────────┘
              ▼
        Node API (Fastify)      ── JWT access 15 мин + refresh 30 дней
              │  WebSocket /realtime?familyId=…
              ▼
        PostgreSQL 16 (docker volume, ежедневный dump)
```

- Мобильное приложение – текущее Expo-приложение: mock-store заменяется на API-store,
  но интерфейс и экраны остаются (правки только в слое данных).
- Realtime нужен ровно для демо-сценария: ребёнок просит доступ → у родителя на втором
  телефоне всплывает запрос → родитель подтверждает → у ребёнка экран меняется сам.
- Аудит-лог пишется на каждое изменение прав и согласий – это ответ на вопрос жюри
  «как вы докажете, что родитель реально давал согласие».

## 3. Модель данных (основное)

| Таблица | Ключевые поля | Зачем |
|---|---|---|
| `users` | id, phone (unique), full_name, status, created_at | клиент банка, вход по номеру |
| `devices` | id, user_id, push_token, os, last_seen_at | сессии и пуши |
| `families` | id, owner_user_id, tariff, invite_code, created_at | пакет «Фэмили» |
| `family_members` | family_id, user_id, role (parent/child), status | состав семьи |
| `children` | id, family_id, user_id, name, birth_date, bracket (7_13/14_17), points | оба возрастных контура |
| `accounts` | id, child_id, kind (pocket/savings/deposit/goal), balance, currency | карманные, копилка, вклад |
| `cards` | id, child_id, last4, status (issued/blocked), issued_at, limits | детская карта |
| `consents` | id, child_id, kind (legal/pd/access/written14), signed_at, signed_by, device_id | 99-З и ГК РБ |
| `permissions` | child_id, product_id, allowed, requires_consent, has_consent | права, выданные родителем |
| `limits` | child_id, monthly, per_txn, pocket_weekly, pocket_day, confirm_each | лимиты |
| `transactions` | id, child_id, card_id, amount, category, merchant, status, created_at | операции, включая отклонённые |
| `goals` | id, child_id, title, emoji, target, saved, auto_save, deadline | копилка и мотивация |
| `quests` | id, child_id, kind (lesson/task), title, points, amount, status, approved_by | геймификация |
| `access_requests` | id, child_id, target, status, created_at, resolved_by, resolved_at | запросы ребёнка |
| `notifications` | id, user_id, kind, title, body, read_at | пуши и лента |
| `audit_log` | id, actor_id, action, entity, entity_id, at | доказательная база |

Жёсткие правила живут **на сервере**, а не только в интерфейсе: категории `gambling` и
`adult` отклоняются на уровне API с кодом 403, даже если клиент подделан. Это то, что стоит
показать жюри.

## 4. API (REST + WebSocket)

Авторизация:
- `POST /auth/otp/request` `{phone}` → `{challengeId, ttl, devCode?}`
- `POST /auth/otp/verify` `{challengeId, code, deviceId}` → `{accessToken, refreshToken, user, family}`
- `POST /auth/refresh`, `POST /auth/logout`, `POST /auth/pin` (установка/проверка кода приложения)

Домен:
- `GET /me`, `GET /family`, `POST /family/children`, `PATCH /children/:id`
- `POST /consents`, `GET /consents`
- `POST /cards/:childId/issue`, `PATCH /cards/:id/block`
- `POST /access/grant`, `DELETE /access/:childId`
- `PATCH /permissions/:childId`, `PATCH /limits/:childId`
- `GET /transactions?childId=&cursor=`, `POST /transactions` (эмулятор оплаты на стенде)
- `PATCH /goals/:id`, `POST /quests/:id/complete`, `PATCH /quests/:id/approve`
- `POST /requests`, `PATCH /requests/:id`
- `WS /realtime?familyId=` – события: `access.granted`, `request.created`,
  `request.resolved`, `txn.created`, `limit.updated`, `quest.approved`, `card.blocked`

## 5. Вход по номеру телефона

1. **A1. Номер** – префикс `+375`, маска `XX XXX-XX-XX`, кнопка «Продолжить»,
   мелким шрифтом согласие на обработку персональных данных (99-З).
2. **A2. Код из SMS** – шесть ячеек, автоподстановка из буфера, таймер повторной отправки.
   На защите: под полем тихая ссылка «Войти демо-кодом» → `1111`.
3. **A3. Код приложения** – 4 или 6 цифр, подтверждение, предложение включить биометрию
   (`expo-local-authentication`).
4. **A4. Возврат в приложение** – экран блокировки: приветствие, кнопка биометрии,
   «Войти другим номером». После третьей ошибки – выход и повторный вход по SMS.
5. **A5. Приглашение ребёнка** – родитель показывает код или QR, ребёнок входит своим
   номером и вводит код приглашения. Роль определяется сервером, а не выбором на экране.

Реальный SMS подключается адаптером (TurboSMS / SMS.by / Twilio) – интерфейс один,
меняется только реализация. Без договора с провайдером демо-режим полностью рабочий.

## 6. Визуальный язык

### Что берём у Искры (БНБ-Банк) – база
- Спокойствие: один акцент на экран, много воздуха, крупные суммы.
- Тёмная тема как полноценный режим, а не «инверсия».
- Три языка (ru / be / en) – у нас уже два, английский добавим при желании.
- Регистрация по номеру → SMS-код → код приложения / биометрия (совпадает с п.5).
- Живая палитра бренда: violet `#A291FF`, teal `#00CCCA`, orange `#FFB143`,
  pink `#FFA1E8`, cream `#FEEDBA` (взято с bnb.by/iskra).

### Что берём у Moby (МТБанк) – детский контур
- Карточная подача: баланс живёт внутри карты, а не в строке таблицы.
- Тёплый дружелюбный тон, крупные иллюстративные элементы, геймификация.
- Яркий акцент допустим, но ровно один на экран.

### Токены (что меняем в текущем приложении)

| Роль | Было | Станет |
|---|---|---|
| Акцент родителя | `#3B5BFD` | `#6C4DF6` (спокойный violet, ближе к Искре) |
| Акцент ребёнка | `#FF7A3D` | `#FF7A3D` (оставляем – это и есть «тепло Moby») |
| Второй акцент | violet + mint + warn одновременно | только teal `#00CCCA` для прогресса |
| Фон / поверхность | `#F4F5FA` / `#FFFFFF` | `#F6F7FB` / `#FFFFFF`, тёмная: `#0E1116` / `#161A21` |
| Градиенты | 4 разных на все случаи | 1 градиент на hero-карту, остальное – плоские поверхности |
| Тени | несколько наборов | одна мягкая: y=8, blur=24, opacity 0.06 |
| Радиусы | 12 / 16 / 20 вперемешку | 24 – карточки, 18 – плитки, 999 – пилюли |
| Типографика | 34 / 28 / 17 / 15 / 13, 800 | 34 / 28 / 17 / 15 / 13, вес 700 максимум, табличные цифры |

### Правила «без шума» (проверяем на каждом экране)
1. Один акцентный цвет и не больше двух фоновых поверхностей на экран.
2. Иконка не получает цветную плашку «просто так» – только там, где несёт смысл
   (сейчас почти каждая строка в цветном квадрате, это главный источник шума).
3. Никаких эмодзи в интерфейсе взрослого контура; в детском – только награды и цель.
4. Одна главная кнопка на экран, вторичные – текстовые.
5. Пустое состояние: иконка, одна строка, одна кнопка.
6. Анимации 200 мс ease-out, без отскоков.

## 7. Что добавляется в приложение

- A1–A4 экраны входа и блокировки (5 экранов).
- A5 приглашение ребёнка по коду/QR.
- Слой данных: API-клиент, refresh токена, оптимистичные апдейты, офлайн-кэш последних
  операций (демо не должно падать, если Wi-Fi на площадке моргнёт).
- Тёмная тема и переключатель в настройках.
- Настройки: язык, тема, устройства, выход, удаление аккаунта.

## 8. Порядок работ

| Шаг | Что делаем | Оценка |
|---|---|---|
| Э5 | Схема БД в Supabase, seed демо-данных – **сделано** | – |
| Э6 | API: OTP, JWT, семья/дети/права/лимиты/операции/цели/квесты, WebSocket – **код готов** | – |
| Э7 | Экраны входа и API-клиент – **готовы**, осталось перевести экраны данных на API | 0.5 дня |
| Э8 | Реалтайм-сценарий на двух телефонах + эмулятор оплаты | 0.5–1 день |
| Э9 | Дизайн-проход «без шума», тёмная тема, APK, видео | 0.5 дня |

Критический путь: Э5 → Э6 → Э7 → Э8. Если время поджимает, Э9 урезается, но вход и
реалтайм не выкидываются – именно они показывают «настоящий банк».

## 9. Что уже сделано и что нужно от вас

Сделано:
- Схема базы (`supabase/migrations/0001_init.sql`) и демо-данные (`supabase/seed.sql`).
- Node API: `server/` – OTP, JWT с refresh, семья, дети, согласия, права, лимиты,
  операции с серверной проверкой правил, цели, квесты, запросы, уведомления, аудит, WebSocket.
- Экраны входа в приложении: номер → код (демо `1111`) → код приложения → экран блокировки,
  создание семьи и вход ребёнка по коду доступа.

Нужно от вас:
1. **Supabase**: создать проект на supabase.com, применить миграцию и прислать
   Project URL и service_role key (или дать доступ к аккаунту).
2. **Сервер**: IP VPS, логин для деплоя и домен (например `api.moby-family.by`),
   направленный A-записью на этот IP. Пошаговая инструкция – в [DEPLOY.md](DEPLOY.md).
3. **SMS**: решено – демо-код `1111`; адаптер под провайдера оставлен за интерфейсом.
4. **Ссылки**: скриншоты Moby из App Store / Google Play – сайт moby.by из моей среды
   не открывается, поэтому Moby описываю по общему представлению, а Искру – по их
   странице [bnb.by/iskra](https://bnb.by/iskra/).
