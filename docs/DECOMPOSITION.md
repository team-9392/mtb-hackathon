# Moby Family – декомпозиция на утверждение

**Версия 0.1** · подготовлено по ТЗ «Хакатон „Детско-семейный банкинг в Moby"» (пп. 2, 3, 4, 5, 6).
Цель документа: утвердить состав ролей, экранов и цифры экономики **до** написания кода.
Код не требуется пунктом 6 ТЗ, поэтому приложение проектируется как один сквозной демо-сценарий, который запускается с физических iPhone и Android на защите.

## 1. Концепция в пяти строках

1. Родитель оформляет **семейный пакет Moby Family** и выбирает возрастную ветку ребёнка: **7–13** или **14–17**.
2. Банк выпускает ребёнку карту (физическую + мгновенно виртуальную), родитель – сторона договора и распорядитель.
3. Ребёнок получает **выданный родителем доступ** в Moby с урезанными правами; родитель в любой момент меняет права и лимиты или отзывает доступ.
4. Внутри – «карманные деньги», цель накопления, вклад, страховка, партнёрские скидки, уроки финансовой грамотности с наградами.
5. Родитель видит прогресс ребёнка; банк получает оборот, остатки и **будущего взрослого клиента**.

## 2. Роли и правовые ветки

### 2.1 Роли

| Роль | Кто это | Ключевые возможности | Ограничения |
|---|---|---|---|
| **Родитель** (владелец пакета) | законный представитель, клиент Moby | оформление, согласия, выпуск продуктов, матрица прав, лимиты, подтверждение операций, блокировка карты, видит операции и прогресс ребёнка | – |
| **Ребёнок 7–13** | недееспособный | тратит карманные, копит на цель, проходит уроки/квесты, запрашивает доступ к продукту | нет своего счёта и вклада, нет переводов/онлайн-платежей без подтверждения родителя, доступ в Moby выдан и отзывается родителем |
| **Ребёнок 14–17** | частичная дееспособность | распоряжается своими средствами, открывает вклад в свою пользу, часть операций с письменного согласия | крупные сделки – с письменного согласия законного представителя; hard-блок 18+ и азартных игр |
| **Банк / партнёры** | вне экрана | выпуск, скоринг, кешбэк, партнёрские офферы | – |

### 2.2 Матрица прав (то, что должно быть видно в UI)

| Действие | 7–13 | 14–17 | Основание |
|---|---|---|---|
| Банковская карта | доп. карта к счёту родителя, ребёнок – держатель | своя карта к своему счёту | ГК РБ (ст. 25/26), инструкция НБРБ по картам – **уточнить формулировки** |
| Свой счёт / вклад | нет | да, вклады в свою пользу | ГК РБ ст. 26 |
| Карманные деньги от родителя | да | да | договор |
| Переводы другим лицам | по подтверждению родителя | самостоятельно в пределах лимита | родительский контроль |
| Онлайн-платежи | только в разрешённых категориях | в разрешённых категориях | правила пакета |
| Снятие наличных | по подтверждению | в пределах лимита | родительский контроль |
| Страховка ребёнка, подписки | оформляет родитель | 14+ – с письменного согласия | ГК РБ ст. 26 |
| Доступ в Moby | выдан родителем, отзываемый | выдан родителем, отзываемый | п. 2 ТЗ |
| Азартные игры, категории 18+ | **заблокировано в ядре** | **заблокировано в ядре** | п. 4.1 (hard-rule, не настройка) |

### 2.3 Артефакты согласий (обязательны в интерфейсе родителя)

1. Согласие законного представителя на открытие продуктов ребёнку.
2. Согласие на обработку персональных данных ребёнка (Закон РБ № 99-З) – с возможностью отзыва.
3. Подтверждение предоставления ребёнку доступа в Moby.
4. Отдельное письменное согласие для операций 14–17, требующих согласия.
5. Экран «потеря карты / спорная операция» – порядок действий.

## 4. Модель данных (mock, без бэкенда)

Family, User(parent|child), ChildProfile(ageBracket), Account, Card(status), Limit(period, amount, category), Permission(product, operation, allowed), Transaction, Goal(target, progress), Quest(from, reward, status), Lesson, Reward/Points, Consent(type, signedAt, revokedAt), AccessRequest(product, status), Notification.

Правила, которые живут в логике, а не в UI:
- категории 18+ и азартные игры – блок на уровне движка разрешений;
- возрастная ветка меняет доступный набор продуктов и требует/не требует согласия;
- изменение матрицы прав родителем мгновенно перерисовывает доступные действия ребёнка;
- отзыв доступа родителем закрывает сессию ребёнка.

## 5. Экономика в цифрах

Все значения – **допущения для защиты**, их нужно подтвердить (см. 5.10). Валюта – BYN.

### 5.1 Допущения (базовый сценарий)

| Параметр | Значение |
|---|---|
| Детей 7–17 в Беларуси | ~1,0 млн (оценка, проверить по Белстату) |
| Семей с детьми 7–17 | ~700 тыс. |
| Привлечено семей: Y1 / Y2 / Y3 | 2 800 / 10 500 / 24 500 (0,4% / 1,5% / 3,5%) |
| Оборот ребёнка в месяц | 300 |
| Инкрементальный оборот родителя в месяц | 2 100 |
| Остаток ребёнка (цель накопления) | 500 |
| Инкрементальный остаток родителя | 2 000 |
| Интерчейндж | 1,0% оборота |
| Маржа на остаток (фондирование) | 7% годовых |
| Комиссии: страховка + партнёры + подписки | 45 / год |
| Обслуживание ребёнка (карта, поддержка, push) | 25 / год |
| Кешбэк семье | 1% на оборот, потолок **15 / мес**, утилизация 60% → 108 / год |
| Welcome-бонус | 30 разово |
| CAC семьи | 35 |
| Churn | 12% / год |
| Разовые затраты на запуск (ИТ, интеграции) | 150 000–200 000 |

### 5.2 P&L одной семьи за год

| Статья | Расчёт | BYN/год |
|---|---|---|
| Интерчейндж | 1% × 2 400 × 12 | 288 |
| Маржа на остаток | 7% × 2 500 | 175 |
| Комиссии и партнёры | – | 45 |
| **Выручка** | | **508** |
| Обслуживание ребёнка | – | −25 |
| Кешбэк и бонусы | 108 (+30 в Y1) | −108 |
| **Contribution margin** | | **375** (Y1 – 345) |

- **Payback:** (35 + 30) / (375 / 12) = **2,1 мес.**
- **LTV** за 5 лет с учётом churn 12%: ≈ 1 480 BYN → **LTV / CAC ≈ 42.**

### 5.3 Изолированный детский пакет – почему без семьи он не работает

| Статья | BYN/год |
|---|---|
| Интерчейндж 1% × 300 × 12 | 36 |
| Маржа на остаток 7% × 500 | 35 |
| Комиссии | 15 |
| **Выручка** | **86** |
| Обслуживание + кешбэк (36) | −61 |
| **Contribution** | **25** |

Payback: 65 / 25 × 12 = **31 мес.** Детская карта окупается только как **канал привлечения семьи**. Порог: инкрементальный оборот родителя или остаток, покрывающий разрыв 40 BYN/год (≈ 335 BYN/год оборота или ≈ 570 BYN остатка).

### 5.4 Ловушка программы лояльности (обязательный слайд)

| Вариант кешбэка | Затраты/год | Contribution |
|---|---|---|
| 1% с потолком 15 BYN/мес (базовый) | 108 | **+375** |
| 1% без потолка | 288 | +195 |
| 2% без потолка | 576 | **−93 (убыток)** |

Вывод для канваса: оборотный кешбэк в РБ **выше интерчейнджа**, поэтому кешбэк – только 1% в 3–4 семейных категориях с жёстким потолком; «жирные» скидки даёт партнёр (CPA), а не банк.

### 5.5 Геймификация – почти бесплатно

1 урок = 20 баллов, 1 балл = 0,01 BYN → 0,2 BYN за урок; 12 уроков/год ≈ **2,4 BYN/ребёнок**. Награды за задания родителя – перевод из карманных (не расход банка). Партнёрские призы – за счёт партнёра. Геймификация – инструмент удержания, а не строка затрат.

### 5.6 Чувствительность (payback, мес.)

| CAC ↓ / остаток семьи → | 1 500 | 2 500 | 4 000 |
|---|---|---|---|
| 35 | 2,6 | 2,1 | 1,6 |
| 80 | 4,3 | 3,5 | 2,8 |
| 150 | 7,1 | 5,8 | 4,5 |

Даже при CAC 150 BYN окупаемость < 8 месяцев.

### 5.7 Эффект «будущий взрослый клиент» (цель из п. 1 ТЗ)

24 500 детей × удержание 70% × LTV взрослого клиента 2 500 BYN ≈ **+43 млн BYN отложенной выручки** к Y3. Отдельная инвестиция не нужна – это побочный эффект пакета.

### 5.8 Окупаемость программы

Разовые 175 000 BYN. Y1: 2 800 семей × 375 = **1,05 млн BYN** contribution → инвестиция окупается **внутри первого года** (≈ 2 мес. после запуска). Y3: 24 500 × 375 ≈ **9,2 млн BYN/год**.

### 5.9 Формулировка «Win-Win» для п. 4.2

- **Банку выгодно, если:** детский пакет продаётся вместе с семейным счётом/вкладом; удаётся удержать родителя (инкрементальный остаток ≥ 500–2 000 BYN); кешбэк ограничен потолком; доля цифрового онбординга высокая (CAC ≤ 100).
- **Банку невыгодно, если:** продавать карту ребёнку «в одиночку», без родительского оборота и остатков (payback 31 мес.), или включить неограниченный кешбэк 2% (отрицательная маржа).
- **Семье выгодно:** бесплатное обслуживание при остатке, кешбэк в аптеках/детских товарах, скидки партнёров, страховка ребёнка со скидкой, управление в одном приложении, обучение ребёнка без затрат.
- **Условие устойчивости:** доля семей, где пакет повысил остаток родителя, ≥ 40%; иначе модель сводится к изолированному детскому P&L (5.3).

### 5.10 Что нужно проверить до сдачи

1. Число детей 7–17 и семей в РБ (Белстат).
2. Реальный интерчейндж MTBank и стоимость обслуживания карты.
3. Средний оборот и остаток по семейному сегменту.
4. Требования НБРБ и ГК РБ к картам несовершеннолетних (формулировки ст. 25/26).
5. Название пакета и брендинг (нужно для UI).

## 6. Сценарий демо на защите (3–4 мин, два телефона)

| Время | Что происходит |
|---|---|
| 0:00 | iPhone – «Родитель», Android – «Ребёнок» (или наоборот), оба запущены из Expo Go по QR |
| 0:20 | P1 оффер → P2 выбор возраста 7–13 → P3 согласия → P4 выпуск карты (виртуальная сразу, физическая «в доставке») |
| 1:20 | P5 выдача доступа → на телефоне ребёнка доступ появляется в реальном времени |
| 1:40 | C1 дом ребёнка: баланс, карманные; C3 расписание |
| 2:00 | P7 лимит 20 BYN и запрет 18+/азартных игр → C6 показывает «недоступно и почему» |
| 2:20 | C4 квест «Урок: что такое копилка» → награда; C2 цель «самокат 300 BYN» → прогресс |
| 2:50 | C5 запрос доступа к вкладу → на P6 приходит уведомление → родитель одобряет → ребёнок видит новый продукт |
| 3:20 | P9 прогресс ребёнка глазами родителя |
| 3:40 | Слайд экономики: 2,1 мес. окупаемость, 43 млн отложенного LTV |

**Фолбэк:** при падении Wi-Fi/Metro – demo-mode на одном телефоне + заранее записанное видео. Wi-Fi хакатона часто изолирует устройства → стартовать через npx expo start --tunnel.

**Резервная поставка:** APK для Android через EAS – ставится на любой телефон без магазина. Для iPhone аналог без Apple Developer невозможен, поэтому основной канал – Expo Go.

## 8. Риски

| Риск | Митигация |
|---|---|
| Expo Go не видит ноутбук по Wi-Fi | --tunnel + резервный demo-mode на одном устройстве |
| Нет интернета в день защиты | baseline-сценарий целиком офлайн, синхронизация только как «вау» |
| Не успеваем 20 экранов | режем P1, оставляем 15 must-have |
| Юридическая ошибка в трактовке возраста | явно указать в канвасе: модель опирается на ГК РБ ст. 25/26, формулировки сверяются с юристом банка |
| Плагиат (п. 9 ТЗ) | подчёркиваем новизну: возрастные ветки + выданный/отзываемый доступ + hard-блок 18+ + связка геймификация ↔ родительский контроль |
